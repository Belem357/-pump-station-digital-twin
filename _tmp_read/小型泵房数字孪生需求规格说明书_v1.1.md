## 1. 项目概述

| 项 | 内容 |
|---|---|
| 项目名称 | 小型二供泵房数字孪生监控系统 |
| 项目目标 | 构建基于 Web 的 3D 可视化泵房系统，实现设备状态实时映射、远程下控操作、异常报警及历史数据追溯 |
| 目标用户 | 泵房运维人员、课程评审导师 |
| 核心约束 | 开发周期 3 个月；团队零基础；需支持每周一次导师演示验收 |
| 演示节奏 | **每周三上午**向导师演示一次（v1.1 明确） |
| 硬件条件 | **无真实泵房**，全部设备由软件模拟器（Modbus 模拟器 / PLC 模拟器）顶替（v1.1 明确） |

**"二次供水泵房"是什么**（v1.1 补充，便于零基础成员理解业务）：小区自来水管网压力不足以直供高层，需在中途设泵房加压。典型配置为：进水总管 → 水箱（蓄水缓冲）→ 加压水泵（通常 2 台，一用一备）→ 出水总管 → 用户。本系统监控的就是这一套设备。

## 2. 功能需求矩阵

> **优先级定义**：**P0** = 必做，不做则项目不通过验收；**P1** = 应做，时间不足时可降级或延后。
>
> **"验收标准"列**是判定"这一项做没做成"的唯一依据，开发与验收都看它。

| # | 模块 | 功能名称 | 详细描述 | 优先级 | 验收标准 |
|---|---|---|---|---|---|
| F1 | 3D 场景 | 全景漫游 | 支持鼠标拖拽旋转、滚轮缩放、右键平移；预设"全景 / 水泵 / 水箱"3 个快捷视角 | P0 | 操作流畅无卡顿，帧率 ≥ 30 FPS |
| F2 | 3D 场景 | 设备状态可视化 | 水泵运行时有旋转动画（转速随频率变化）；水箱液位高度随真实数据动态升降 | P0 | 动画与数据延迟 < 500ms |
| F3 | 数据监控 | 实时数据看板 | 侧边栏显示：总出水压力、水箱液位、各泵频率 / 电流 / 温度、今日耗电量 | P0 | 数值与 PLC 模拟器完全一致 |
| F4 | 控制下控 | 单泵手动启停 | 点击 UI 或 3D 模型按钮下发指令，带二次确认弹窗，实时反馈执行结果 | P0 | 指令响应 < 1s，有 Loading 防抖 |
| F5 | 控制下控 | 变频手动调速 | 滑块调节目标频率（0～50Hz），水泵动画转速与 UI 数值同步变化 | P1 | 频率变化时动画平滑过渡 |
| F6 | 报警管理 | 阈值越限报警 | 液位 < 25cm 或液位 > 140cm 或压力 > 0.8MPa 时，触发声光报警，3D 模型对应设备红色闪烁 | P0 | 报警触发准确，无弹窗遗漏 |
| F7 | 报警管理 | 报警记录查询 | 历史报警列表含：时间、设备、类型、状态（已恢复 / 未恢复） | P1 | 支持按时间 / 设备筛选 |
| F8 | 数据监控 | 历史数据曲线 | 图表展示过去 1 小时的压力与液位折线趋势 | P1 | 曲线正确渲染，走势与实际操作吻合 |
| F9 | 系统设置 | 手自动模式切换 | 全局切换模式。自动模式下屏蔽手动按钮，由 PLC 根据液位自动控泵 | P1 | 模式切换即时生效，互斥逻辑正确 |
| F10 | 报警管理 | 低液位联锁停泵 | 液位 < 25cm 持续 30 秒时，PLC 自动切断所有运行中的水泵，防止空转烧毁 | P0 | 联锁可靠触发，且有 30s 防抖，不频繁启停 |

**v1.1 相对 v1.0 的变更标注**：

- **F6**：v1.0 原文为"液位<25cm或压力>0.8MPa"，本次**补入"液位 > 140cm"**。理由：v1.0 定义了液位过低报警却没有过高报警，而水箱溢流是泵房真实存在的风险；数据字典 v1.1 已补 `alarm_level_high` 标签，需 PRD 同步定义阈值。⚠️ **140cm 为暂定值，待 PM 确认。**
- **F8**：v1.0 的功能矩阵中**没有这一项**，但《项目验收清单》4.2 节明确要求"历史曲线：图表组件正确渲染过去 1 小时的压力和液位折线图"，且项目目标里写了"历史数据追溯"。这是 v1.0 的**需求遗漏**——验收要查、PRD 却没定义，等于无据可依。本次补入，优先级定为 P1。
- **F10**：v1.0 的功能矩阵中**没有这一项**，但《核心交互流程图》流程二明确描述了"PLC 内部逻辑检测到低液位，自动切断所有运行水泵"，验收清单 4.4 也要求"水泵自动停止"。同样是需求遗漏，本次补入，优先级 P0（涉及设备安全）。

| 可用性 | 断线时 UI 明确提示，模型保持最后状态 | v1.0 验收清单原有，PRD 未写 | 停掉后端，观察前端表现 |

## 4. 系统边界与不做的事（v1.1 新增）

明确"不做什么"和"做什么"同样重要，否则范围会无限膨胀，三个月做不完。

**本项目做的**：

- 单个小型二供泵房的监控：1 个水箱、2 台水泵、进出水阀门与管道
- 数据的实时监控、可视化、远程控制、报警、历史查询
- Web 端访问（浏览器打开即用）

**本项目明确不做的**：

| 不做的内容 | 原因 |
|---|---|
| 真实硬件对接 | 无真实泵房，全程用模拟器；Modbus 协议层保留，未来换真设备只需改连接地址 |
| 多泵房 / 多站点集中管理 | 超出课程范围，且会使数据模型复杂度翻倍 |
| 用户账号体系与权限分级 | v1.0 安全性要求"记录操作人"，本次以**手动填写操作人姓名**实现，不做登录注册。若导师要求，第 10 周后评估 |
| AI 问答 / 智能诊断 / 预测性维护 | 现有需求与分工方案中均无此项，不纳入范围 |
| 移动端 App / 小程序适配 | PRD 已限定 Chrome / Edge 桌面浏览器，1920×1080 分辨率 |
| 报表导出（Excel / PDF） | 无需求来源，不做 |
| 视频监控系统接入 | 无硬件条件，不做 |

## 5. 角色与分工（v1.1 新增）

> v1.0 未写明项目由谁完成，导致排期与责任无法落地。本节依据《AI 辅助数字孪生系统建设》分工方案补入。

| 角色 | 职责 | 本项目中的关键产出 |
|---|---|---|
| 传感器与设备模拟工程师 | 用软件模拟泵房设备，产生数据、接收指令 | 模拟器 + I/O 点表 + Modbus 地址建点 |
| 协议解析工程师 | 读取模拟器数据并翻译成统一标签名 | 采集程序 + 标签映射配置 + 缩放换算 |
| 后端工程师 | 存数据、推送数据、接收并转发控制指令 | FastAPI 服务 + WebSocket + 数据库 |
| 三维模型工程师 | 用 Blender 建泵房 3D 模型 | glb 模型 + 节点命名符合规范 |
| 前端工程师 | 搭网页、加载模型、数据驱动动画与交互 | Three.js 页面 + 控制面板 + 数据绑定 |
| 产品经理 | 定义需求边界、协调接口、制定验收标准、盯进度 | 本 PRD + 交互流程图 + 接口规范 + 验收清单 |

**关于"AI 工程师"**：现有分工方案与四份文档中**均无此岗位、也无 AI 类功能需求**，故本项目不设该角色。设备与数据模拟相关职责由传感器与设备模拟工程师承担。如后续确需新增 AI 功能（如自然语言问答、故障智能诊断），须先由 PM 评估工期影响再决定是否纳入——**三个月工期已排满，新增功能需砍掉等量的 P1 功能**。

**数据流向**：

```
[传感器: 造数据] → [协议解析: 读取+翻译] → [后端: 存储+推送] → [前端: 显示+驱动3D]
                                                    ↑                      ↓
                                          [写 Modbus 线圈] ← ← ← [控制指令下发]
                                                          [三维: 提供 glb 模型] →
        [产品经理: 定字段命名规范、协调接口、验收 —— 贯穿全程]
```

## 6. 12 周里程碑（v1.1 新增）

> v1.0 只写了"开发周期 3 个月"，没有分解，无法判断进度是否正常。本节补入四个阶段里程碑。

| 阶段 | 周次 | 阶段目标 | 里程碑验收物 |
|---|---|---|---|
| 一、打地基 | 第 1～2 周 | 环境就绪、跑通各自最小例子、统一字段规范 | 六人环境全部可用；《统一字段命名表》发布；Modbus 地址表回填确认 |
| 二、通数据 | 第 3～4 周 | 打通"模拟器 → 协议解析 → 后端 → 前端 3D"全链路 | **F1、F2、F3（液位与压力部分）可用**：3D 泵房能显示，改模拟器液位，水箱水面跟着升降 |
| 三、加功能 | 第 5～8 周 | 依次实现控制、动画、报警、看板 | **F4、F5、F6、F10、F3 全部可用**：能远程启停、水泵会转、越限会报警联锁、看板数值齐全 |
| 四、补完善 | 第 9～12 周 | 历史数据、模式切换、优化、文档定稿 | **F7、F8、F9 可用**；全部 83 项验收通过；四份文档定稿 |

**里程碑判定原则**：

- 每个阶段末的里程碑**必须达成**才能进入下一阶段；达不成则**砍 P1 保 P0**，不推迟整体工期
- 第 4 周末的里程碑（3D 水箱随液位升降）是**全项目最关键的一个**——它证明整条技术路线走得通。这一项若失败，须立即向导师求助，不要闷头往下做
- 每周三演示后，PM 依据导师反馈调整后续周次安排，并同步更新本文档版本号

## 8. 术语表（v1.1 新增，便于零基础成员与导师沟通）

| 术语 | 解释 |
|---|---|
| 数字孪生 | 真实设备在电脑里的"实时分身"，真实设备状态变化时 3D 模型同步变化 |
| 二供 / 二次供水 | 城市管网压力不足时，通过泵房二次加压向高层用户供水的系统 |
| PLC | 可编程逻辑控制器，工业现场的控制核心。本项目用软件模拟器代替 |
| Modbus | 一种简单常用的工业通信协议。本项目用 Modbus TCP |
| 保持寄存器 | Modbus 中存放数值的地址单元（可读可写），本项目用于存液位、压力、频率等 |
| 线圈 | Modbus 中存放开关量的地址单元，本项目用于下发启停指令 |
| 变频器 / 变频调速 | 通过改变电机供电频率来调节转速。频率越高转速越快，本项目范围 0～50Hz |
| 联锁 | 一个条件触发后自动执行的保护动作，如"液位过低 → 自动停泵" |
| 防抖 | 避免数值在阈值附近波动时系统频繁翻转状态的保护机制 |
| WebSocket | 服务端可持续主动向浏览器推送数据的通信通道，适合实时数据 |
| glb / glTF | 3D 模型的文件格式，Blender 导出、Three.js 加载 |
| FPS | 每秒帧数，衡量画面流畅度，≥30 为可接受 |
