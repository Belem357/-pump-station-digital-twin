## 一、本文档的定位与边界

### 1.1 它是什么

**原《传感器推荐型号表》只给了"选了什么"，没给"为什么选它、为什么没选别的"。本文档补的就是这一段论证。**

型号的原始出处是一张《传感器推荐型号表》图片，已录入 `代码/backend/devices.json` 的 `sensorsSummary` 段，前端讲解卡片直接读它。**该图片现已不可查**（判断为早前在对话中直接粘贴上传、未存成文件）。因此 **v1.1 起改用厂商官方公开资料逐个核实，v1.2 起按厂商资料定案并回改 `devices.json`**——来源见第七节，核实结论见第五节。本文档是该表配套的**选型理由说明**，用于：

1. **答辩讲解**——被问到"为什么用这个型号"时有话可说
2. **模拟器建点的物理依据**——① 号角色要知道每个测点的量程从哪来
3. **将来真采购的参考**——换成真实泵房时按此清单询价

### 1.2 它不是什么

**本项目没有真实泵房，传感器由 Modbus 模拟器顶替，不存在采购行为。** 所以本文档是**工程论证**，不是采购合同，也不代表已经和任何厂商询过价。文中所有价格比较均为"量级关系"，不是报价。

另外要划清一条界线：

> **信号制式（4-20mA）是真知识，型号是参考值。**
>
> 答辩时"为什么全项目用 4-20mA 而不是 0-10V"这类问题，答案是硬标准，怎么问都站得住；而"为什么是 MPM4700 而不是别家同类"这类问题，本质是性价比选择，答"同级别国产主流型号、性价比合适"即可，不必编造技术壁垒。

## 二、三条全局选型原则

先定原则再选型号。本项目所有传感器都遵守下面三条，**理解这三条比记住型号重要**。

### 原则 1：信号制式统一到 4-20mA 电流环

这是全项目最核心的一条，也是答辩必被问的一条。

**为什么用 4-20mA，而不是 0-10V / 0-5V 电压信号？**

| 理由 | 说明 |
|---|---|
| 抗干扰 | 泵房里有变频器，变频器是强电磁干扰源。电流环是低阻抗回路，外界感应的干扰电压很难改变回路电流；电压信号是高阻抗回路，干扰直接叠加到读数上，表现为数值乱跳 |
| 远距离不衰减 | 导线有电阻。电压信号经过长电缆后会有压降，读数偏低；电流环只要供电电压够，无论线阻多大回路电流都是 20mA，读数不变 |
| 断线可检测 | **这是报警系统最看重的一点**：0mA 表示断线/故障，4mA 表示量程零点，两者可区分。而 0-10V 方案里 0V 既可能是"最小值"也可能是"断线"，无法分辨——传感器坏了系统却以为液位正常，这在供水系统里是致命的 |
| 两线制省线 | 电源和信号共用一对线，液位变送器只需要两根线，敷设成本低 |

**为什么不全用 RS485 数字量？**

RS485 抗干扰更强、还能传多参数，但：仪表单价更高、每台要配置地址和波特率、还要加 RS485→TCP 网关才能进本项目链路。**本项目只在"需要本地智能计量"的地方用 RS485——也就是电度表**，其余四类全部走 4-20mA。这是成本与复杂度的权衡，不是技术好坏。

### 原则 2：精度统一 0.5%FS，不追 0.2% / 0.1%

**0.5%FS 是什么意思**：满量程（Full Scale）的 0.5%。液位量程 150cm 时，误差 ±0.75cm。

**够不够用？算一下**：本项目液位报警阈值是 25cm（低液位联锁停泵）和 140cm（高液位防溢流），阈值离量程两端各有几十厘米余量。±0.75cm 的误差相对于这个余量完全可忽略。

**为什么不选更高精度**：

1. **贵**。0.2 级仪表价格通常是 0.5 级的 1.5~2 倍，本项目要在教学预算内配齐 5 类传感器
2. **无收益**。系统的整体精度不止取决于传感器，还受采集模块的 AD 位数、变送器、线缆等各环节限制。传感器精度超过系统瓶颈（瓶颈在采集侧）就是浪费
3. **报警系统看的是可靠性不看分辨率**。报警阈值离坏值有几十厘米余量，0.1cm 的分辨率不会让报警更准

**⭐ 补充一个核实后才发现的事实：本项目的 0.5%FS 不是我方主动"降配"，而是小量程缩放档的厂商给定指标。**

MPM4700 的标称综合精度典型值是 ±0.1%FS——比 0.5%FS 好得多。但官方资料明确说明：**3.5mH₂O、7mH₂O 等小量程段经"量程缩放"后，综合精度典型值为 ±0.5%FS**。本项目为了匹配 150cm 水箱而用了缩放档，所以 0.5%FS 是选量程的结果，不是我方填错了数。详见 3.1 节。

**唯一的例外是电度表**：电能计量有法规性质，精度要求本来就比一般测点高，它的指标是**有功 0.5S 级 / 无功 2 级**——这不是我们选的，是行业规定的。详见 3.5 节。

### 原则 3：供电统一 24VDC

| 理由 | 说明 |
|---|---|
| 泵房标准 | 24VDC 是工业控制柜的标准直流电压，开关电源随处可得 |
| 安全 | 24V 属于安全电压等级范围，检修时触电风险低，湿环境（泵房）尤其重要 |
| 备件好买 | 24V 两线制变送器是市场主流，选型面最宽 |
| 唯一例外 | 电度表 DTSD1352 是 **220VAC** 供电——电度表要接在计量回路上，自带电源模块 |

## 三、逐个测点的选型对比

### 3.1 液位 —— MPM4700 投入式液位变送器

| 项 | 值 |
|---|---|
| 型号 | MPM4700 |
| 品牌 | 麦克传感 |
| 量程 | 0~2mH₂O |
| 输出 | 4-20mA（两线制） |
| 精度 | 0.5%FS |
| 供电 | 24VDC |

**候选方案对比：**

| 方案 | 优点 | 否掉的理由 |
|---|---|---|
| **投入式静压（选中）** | 便宜、输出连续量、4-20mA 标准、量程可小到 1m、结构简单 | 探头接触水，长期可能结垢堵塞 |
| 超声波 | 非接触、无结垢问题 | 水箱是密闭空间，有水汽凝露，超声波受温度/湿度/泡沫影响大；有安装盲区。150cm 的小水箱里盲区占比过大 |
| 雷达 | 精度高、穿透强、非接触 | 价格是投入式的数倍；其优势（大量程、强穿透）在 150cm 小水箱里完全用不上 |
| 浮球开关 | 极便宜、极可靠 | **只有"高/低"两个开关量，测不出连续液位** |
| 电容式 / 磁致伸缩 | 精度高 | 价格高，多用于油罐等高精度场合，本项目用不上 |

**关键否掉理由**：浮球开关是这里最重要的反例。它便宜可靠，但**本项目第 4 周的核心里程碑是"3D 水箱随液位升降"，这要求液位必须是连续量**。浮球只能输出"到没到"两个状态，做不出连续升降的动画。这是需求直接排除的，不是成本问题。

**⭐ 关于量程 0~2mH₂O —— 这是本文档最需要说清的一点**

对照麦克传感官方资料，MPM4700 的**标准量程档位**是：3.5、7、10、20、35、70、100、200 mH₂O，**其中并没有 2m 这一档**。

那 `devices.json` 里的 0~2mH₂O 从哪来？来自 MPM4700 的**量程缩放**功能——官方说明"量程缩放最小为基本量程的 1/5"，即拿 10mH₂O 的基本量程缩到 1/5，得到 0~2mH₂O。

**这不是笔误，而是本项目的主动选择：**

| | 选 **0~2mH₂O**（10m 档缩放） | 选 3.5mH₂O（最小标准档） |
|---|---|---|
| 覆盖 150cm 水箱 | 够（1.33 倍余量） | 够（2.33 倍余量） |
| 精度 | ±0.5%FS | ±0.5%FS |
| **换算成绝对误差** | **±1.0cm** | ±1.75cm |
| 结论 | ✅ **选它** | 量程过大，绝对误差反而更差 |

**要点：精度指标是"满量程的百分比"，所以量程选得越大，绝对误差越大。** 用一个刚好覆盖的缩放档，比用一个宽松的标准档更准。这才是选 0~2mH₂O 而不是 3.5mH₂O 的真正理由。

**这也顺带解释了 `devices.json` 里"精度 0.5%FS"的来源**：MPM4700 非缩放档的综合精度典型值是 ±0.1%FS，而官方明确说明小量程段**经量程缩放后典型值为 ±0.5%FS**。本项目用的正是缩放档，所以 0.5%FS 是厂商指标，不是我方随意填写。

**⚠️ 边界说明（答辩可能被追问）**：MPM4700 除标准 4-20mA 两线制外，**还可选配 RS485（自定义协议或 Modbus RTU）或 HART 接口**。本项目选 4-20mA 是遵循第二节原则 1——统一模拟量制式，不为一个测点单独加网关。**如果被问"这表不是能直接出 RS485 吗"，答法就是这一句。**

**关于结垢风险**：投入式的固有缺点是探头接触水。本项目的介质是市政自来水，水质好，风险低。**若将来这套系统改用于污水泵站，液位必须换成超声波**——这一点建议答辩时主动提，能体现你懂选型的边界条件。

### 3.2 压力 —— MPM480 压力变送器

| 项 | 值 |
|---|---|
| 型号 | MPM480 |
| 品牌 | 麦克传感 |
| 量程 | 0~1.0MPa |
| 输出 | 4-20mA |
| 精度 | 0.5%FS |
| 供电 | 24VDC |

**候选方案对比：**

| 方案 | 优点 | 否掉的理由 |
|---|---|---|
| **扩散硅 + 不锈钢隔离膜片（选中）** | 耐水锤冲击、耐腐蚀、工业标配 | — |
| 陶瓷电容式 | 抗过载能力强、成本略低 | 抗水锤和抗振动不如不锈钢膜片结构 |
| 一般膜片式（非隔离） | 便宜、精度好 | 膜片直接接触介质，泵房水锤冲击下易损坏 |

**两个选型要点：**

1. **为什么选不锈钢隔离膜片**：这个测点装在出水总管上，水泵启停和变频调速会产生**水锤**（压力冲击，瞬时压力可达正常值的数倍）。隔离膜片结构能把介质和敏感元件分开，抗冲击、抗腐蚀。
2. **量程上限必须高于报警阈值**：本项目超压报警阈值定为 **0.8MPa**，量程上限选 1.0MPa，留了 1.25 倍余量。
   **不能选 0.6MPa 量程**——那样报警点就压在满量程附近，既测不准又可能在传感器饱和区工作，报警形同虚设。这是选量程时最容易犯的错：**先看报警阈值，再选量程上限，最后才看正常工况值。**

**型号已定案：MPM4800 → MPM480（v1.2 变更）**

原《传感器推荐型号表》写的是"MPM4800"，但核实厂商资料时发现：**同厂的 MPM480 资料非常完整**（官网产品页、操作手册、数据表齐全），而"**MPM4800**"在公开资料里几乎查不到独立规格——全项目只在一个第三方应用文档里见到一次提法，且那个量程（0~5 米水柱）看着更像液位表的用法。

**已按厂商资料改为 MPM480。** 理由：资料可查、市场常见、答辩被追问时有官方依据可引，而且本项目需要的"不锈钢隔离膜片 + 4-20mA 两线制 + 精度 0.5%FS"它全部满足。`devices.json` 已同步修改。

**MPM480 的可核实参数**：

| 项 | 值 |
|---|---|
| 量程 | -0.1…0 ～ 0.01…100 MPa 可选（**0~1.0MPa 在可选范围内**） |
| 输出 | 4-20mADC 两线制（也可选 0~10/20mADC、0/1~5/10VDC） |
| 供电 | 15~30VDC |
| 综合精度 | **典型 0.25%FS、最大 0.5%FS** |
| 膜片 / 壳体 | 不锈钢 316L / 不锈钢 1Cr18Ni9Ti |
| 防护等级 | IP65 |

**注意精度那一行**：`devices.json` 里写的 `0.5%FS` 对应的是 MPM480 的**最大值**（典型值是 0.25%FS）——这是保守取值，方向是对的，不用改。

**⚠️ 一处与 3D 模型的出入，答辩时要心里有数**：`泵房.glb` 里这个位置的模型节点叫 **`压力表表盘` / `压力表表颈`**——那是**机械指针压力表**，不是变送器。详见 5.6 节。

### 3.3 温度 —— PT100 装配式铂电阻 + 一体化变送器

| 项 | 值 |
|---|---|
| 型号 | PT100 |
| 品牌 | 通用件，各厂都有 |
| 量程 | 0~150℃ |
| 输出 | 4-20mA（PT100 三线制输入） |
| 精度 | 0.5%FS |
| 供电 | 24VDC |

**候选方案对比：**

| 方案 | 优点 | 否掉的理由 |
|---|---|---|
| **PT100 铂电阻（选中）** | 线性度最好、工业标准、三线制可消除导线电阻误差、配一体化变送器直接输出 4-20mA | 成本略高于热敏电阻 |
| 热电偶（K 型） | 可测 400℃ 以上高温、结构简单 | 本项目只要 0~150℃，用不上其高温优势；冷端补偿麻烦，精度通常 ±1~2℃，不如 PT100 |
| DS18B20 数字温度传感器 | 便宜、精度尚可、单总线可挂多个 | 单总线抗干扰不如电流环；需要 MCU 驱动，接 PLC 要额外转换。适合单片机小项目，不适合工业控制柜 |
| NTC 热敏电阻 | 极便宜、灵敏度高 | **非线性严重**、一致性差、需要查表换算，互换性差。适合家电，不适合本项目 |

**"装配式"和"一体化变送器"分别是什么意思：**

- **装配式**：铂电阻元件装在一个带螺纹的金属保护套里，可以直接拧到电机外壳或轴承座上，不用改造电机
- **一体化变送器**：把"铂电阻阻值变化"转换成"4-20mA 电流"的模块，装在接线盒里。**没有它，PT100 输出的是电阻值，PLC 的模拟量输入模块读不了**

**三线制的作用**：PT100 靠自身电阻变化测温（0℃ 时 100Ω），导线本身也有电阻，两线制会把导线电阻也算进温度。三线制用第三根线做补偿，把这部分误差消掉。

### 3.4 电流 —— BH-0.66 电流互感器 + 电流变送器

| 项 | 值 |
|---|---|
| 型号 | BH-0.66 |
| 品牌 | 通用件 |
| 量程 | 0~20A |
| 输出 | 4-20mA |
| 精度 | 0.5%FS |
| 供电 | 24VDC |

**候选方案对比：**

| 方案 | 优点 | 否掉的理由 |
|---|---|---|
| **互感器 + 变送器（选中）** | 不用改动主回路接线、开口式可不停电安装、泵房电控柜标配 | 多一个硬件 |
| 霍尔电流传感器 | 精度高、可测直流、响应快 | 价格高；本项目是交流电机，用不上其直流优势 |
| 直接从变频器读电流 | **零硬件成本**，变频器本身经 RS485 上报输出电流 | 见下方说明 |

**⚠️ 这里有一个必须主动说明的点：**

**严格来说，本项目最省的方案是"直接从变频器读电流"**——变频器通过 RS485 Modbus 上报实时输出电流，读寄存器就行，一个硬件都不用装。

**那为什么清单里还保留互感器方案？** 原因有三，答辩时请主动讲清楚，否则被问到会答不上来：

1. 泵房电控柜里**电流互感器本来就是真实标配**，主要用途是电机保护和电表计量，不是为了监控系统才装的
2. 本项目的电流是"旁路计量"——独立于变频器自身上报的数据，两条来源可以互相校核
3. 教学场景下硬件方案在讲解中更完整（有实物可讲）

**如果被问"那到底用哪个"**，标准答法是：**模拟器阶段两者等价（都是往寄存器里写数）；真实泵房推荐直接读变频器，把互感器留给电机保护用。**

**关于 BH-0.66**：`0.66` 表示额定电压 0.66kV 电压等级，这是低压电流互感器的常见型号系列。**开口式**（可卡在已有电缆上，不用拆线）是它在本项目里的选型理由——改造已有泵房时不用停电、不用断开主回路。

**关于量程 0~20A**：`devices.json` 里记录水泵满频运行时电流约 15A。选 0~20A 留了约 1.3 倍余量，既能覆盖满负荷，又不会因为量程过大而牺牲小电流时的分辨率。

### 3.5 电度 —— DTSD1352 三相多功能电能表

| 项 | 值 |
|---|---|
| 型号 | DTSD1352 |
| 品牌 | 安科瑞 Acrel |
| 范围 | 三相四线 |
| 输出 | **RS485 / Modbus RTU** |
| 精度 | **0.5S 级（有功）/ 2 级（无功）** |
| 供电 | 220VAC |

**候选方案对比：**

| 方案 | 优点 | 否掉的理由 |
|---|---|---|
| **带 RS485 的多功能电能表（选中）** | 直接读出总电能/今日电能，带 Modbus RTU 接口，导轨安装 | 单价最高 |
| 脉冲电度表 | 便宜、精度高 | **只输出脉冲**，要 PLC 高速计数器去数脉冲数，丢脉冲就少算电量；而且脉冲表不能直接读出数值 |
| 变频器内部能耗累计 | 零硬件 | 只能算电机耗电，算不了泵房总电（照明、控制柜等）；换变频器数据就丢 |
| **后端软件累加** | 零硬件 | 见下方说明 |

**⚠️ "后端软件累加"是本项目真实讨论过并否掉的方案，值得单独讲：**

项目早期《需求规格说明书 PRD》§9 待决策 #5 的建议是"`today_kwh` 由后端累加"，但这与《接口规范》第四节里 40012~40013 的地址表矛盾（既然有地址，说明模拟器要提供这个数据）。

**最终定为"由电度表提供"（模拟器扮演电度表），否掉后端累加的理由：**

1. **真实的泵房耗电量是电度表"量"出来的，不是算出来的**。后端累加得到的是估算值，不是计量值
2. **后端累加会因为服务重启而丢失累计量**，"今日"这个语义就不成立了
3. 只改 PRD 一处即可，不动 ①② 号角色的接口契约

**精度 0.5S 级（有功）/ 2 级（无功）（v1.2 变更）**：电能计量涉及收费性质，精度要求本来就比一般测点高。原来的写法"0.5 级"是简写，官方规格是**有功电能 0.5S 级、无功电能 2 级**，`devices.json` 已按此修正。

**"0.5S" 里那个 S 是什么意思（这是个加分点）**：S 表示"经互感器接入"（S = 互感器用）。不带 S 的 0.5 级只保证在额定电流**附近**准确；带 S 的 0.5S 级在**很宽的电流范围内**都保持 0.5 级精度。泵房的实际电流随用水量大幅波动（夜间几乎空载、用水高峰满负荷），所以 0.5S 比 0.5 更合适——**这个理由答辩时值得主动说**。

**⚠️ 接口注意（重要）**：这是全项目**唯一**走 RS485 数字量的设备，而 RS485 是**串口（Modbus RTU）**，不是网络口的 Modbus TCP。接真实设备时，这一路需要 **RS485→TCP 网关（或串口服务器）** 转换后才能接入本项目的 Modbus TCP 链路。详见第四节。

## 四、完整信号链路（真实泵房 vs 本项目）

**这是答辩时最容易被追问的地方，务必能画出来：**

```
真实泵房：
  4-20mA 变送器 ──(模拟量电缆)──> PLC 的 AI 采集模块 ──> PLC 内部 Modbus 寄存器
                                                          │
                                                     (Modbus TCP)
                                                          ↓
                                                        后端

  DTSD1352 电度表 ──(RS485/Modbus RTU)──> RS485→TCP 网关 ──(Modbus TCP)──> 后端

本项目（当前）：
  Modbus 模拟器 ──────(Modbus TCP)──────> 后端
```

**关键理解：**

1. **4-20mA 是模拟信号，本身没有地址、不能组网**。它必须先接到 PLC 的模拟量输入（AI）模块，由 PLC 换算成数字量放进保持寄存器，才能被 Modbus 读取。**模拟器顶掉的正是"AI 采集"这一段**，不是 Modbus 协议本身。
2. **RS485 是串口，Modbus TCP 是网络口，两者不是一回事**。电度表这一路需要网关转换。
3. 这正是项目 `README.md` 里"将来接实体泵房，只需把连接地址从模拟器换成真 PLC 的 IP，代码不用改"的确切含义——**省掉的是采集段，协议段和代码段原封不动**。

### 5.6 3D 模型（`泵房.glb`）的核实结果

曾按"型号优先取 `泵房.glb`"的思路解析过 `泵房.glb`（98 节点 / 97 网格 / 12 材质）与 `_工具/泵房_原始导出.glb`。

**结论：GLB 里没有任何型号信息。** 它只有通用构件名（`压力表表盘`、`水箱液位计`、`控制柜指示灯1`…）和颜色材质名（`不锈钢.013`、`泵体蓝.001`、`信号灯红`…），也没有 glTF 的 `extras` 元数据段。**所以型号只能依厂商资料定，即 5.3 节的结论。**

**但 GLB 里读出了三处出入，答辩前要知道：**

| # | GLB 里的实际构件 | 与文档的出入 | 怎么处理 |
|---|---|---|---|
| 1 | `压力表表盘` / `压力表表颈`（挂在出水总管上） | 模型上是**机械指针压力表**，而 `devices.json` 写的是"压力变送器" | 实机上"机械表 + 变送器"并存是常规做法（机械表供现场巡检、变送器给系统采集）。**答辩时若高亮的是指针表，顺口解释一句即可**。也可把 `pipe_main_out.node3d` 由 `pipe_main_out` 改为 `压力表表盘`，让点击热区落在真表上——**此项待确认，会影响前端交互** |
| 2 | `进水手轮` / `进水阀杆` | 模型上进水阀是**手轮（手动阀）**，但项目要远程控制其开度 0~100% | ⚠️ **这是一个真实的建模与需求不一致**。答辩时**不建议主动展示"远程调节进水阀开度"**；若导师问到，如实说模型是最初建的、电动执行机构为后续预留 |
| 3 | 无 `电流互感器` / `电度表` / `温度传感器` 节点 | 与 `devices.json` 中这几项 `node3d: null` 一致（预期内） | 无影响。但 GLB 里有 `水泵1接线盒`——**PT100 的一体化变送器正是装在这种接线盒里**，讲解时可用它当落点 |

**✅ 对得上的部分**：GLB 里有 `控制柜柜体` / `控制柜柜门` / `控制柜显示屏` / `控制柜指示灯1~3`，对应《09.示意图》中的"变频控制柜（变频器 + PLC）"。`水箱液位计` 也与液位测点对得上。

**⚠️ 另外说明**：`devices.json` 里的 `node3d` 字段是给前端点击高亮用的，与本文档的型号无关。前端讲解卡片能正常显示，说明这些节点名是有效的。
