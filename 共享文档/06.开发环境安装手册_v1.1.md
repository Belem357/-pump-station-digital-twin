**项目：小型二供泵房数字孪生监控系统　｜　版本：v1.1　｜　日期：2026-09-24　｜　发放：全组 6 人**

> **v1.1 修订说明**：① 号角色的 ModRSsim2 与 ② 号角色的 pymodbus 都踩到了坑，本次把两个坑写进手册，并新增第 3 节（① ② 号角色直接用现成代码，不用从零写）。

## 一句话说明

**每人装 2~3 样东西，装完能跑通一个最小例子，本关就过了。** 第一周不要求做出任何功能，装不上是正常的，卡住就发群里问。

## 第 0 步：所有人先做这个（3 分钟）

不配这个，后面下 Python 包会慢到你怀疑人生。

打开命令行（按 `Win + R`，输入 `cmd`，回车），粘贴这行，回车：

```
pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/
```

> 如果提示 `pip 不是内部或外部命令`，说明 Python 还没装——先做下面第 1 步，装完 Python 再回来跑这行。

## 第 1 步：先装两样通用的

| 装什么 | 去哪装 | 装好怎么验证 |
|---|---|---|
| **Python** | https://www.python.org/downloads/ 下载 **3.14** 版 | 命令行输入 `python --version`，出现 `Python 3.14.x` |
| **编辑器**（自选一样即可） | VS Code：https://code.visualstudio.com/ ／ Cursor：https://cursor.com/ | 能打开就行 |

> ⚠️ 装 Python 时，安装界面**最底下有个勾选框 `Add Python to PATH`，一定要勾上**。不勾的话命令行找不到 python，后面全崩。这是新手第一号翻车点。

> ⚠️ **全组统一用 Python 3.14**。不要有人装 3.12、有人装 3.11——版本不一致会导致"我这儿能跑，你那儿报错"，排查起来非常痛苦。组长机器上就是这个版本，实测可用。

## 第 2 步：按自己的角色装

### ① 传感器与设备模拟

**要装两样：先装运行库，再装模拟器。**

| 顺序 | 装什么 | 去哪装 |
|---|---|---|
| 1️⃣ | **VC++ 2010 运行库（x86）** | 找组长要 `vcredist_x86_2010.exe`（8.6MB），双击安装 |
| 2️⃣ | **ModRSsim2** | https://sourceforge.net/projects/modrssim2/files/latest/download |

> ⚠️ **为什么必须先装运行库**：ModRSsim2 需要 `mfc100.dll`，而这个文件只在 VC++ 2010 运行库里。新电脑上基本都没有（装了 2012/2013/2022 也不算数，各版本互不通用）。
>
> **不装的后果**：双击 ModRSsim2 没有任何反应，或者窗口一闪就没了——不报错，最容易被误判成"文件坏了"。你会在这上面卡几个小时。

**装好怎么验证**：打开 ModRSsim2，界面里能看到一张寄存器表，手动改一个数值、再读到变化，就算过。

> ModRSsim2 是**免安装**的，下载下来是个单独的 exe，双击就能运行，不用走安装流程。

### ② 协议解析

| | |
|---|---|
| 装什么 | Python 库 `pymodbus`（**版本必须是 3.6.9**） |
| 怎么装 | 见下面第 3 节，有现成代码和 `requirements.txt`，别自己 `pip install pymodbus` |
| 装好验证 | 跑 `python linkCheck.py`，看到 `13 / 13 项通过` 就算过 |
| 调试工具（可选） | QModMaster：https://sourceforge.net/projects/qmodmaster/files/latest/download |

> ⚠️ **绝对不要直接 `pip install pymodbus`**。最新版是 3.15，它的数据存储层正在向 4.0 迁移，经典接口已经被移除，装上会直接报 `ImportError: cannot import name 'ModbusSlaveContext'`。**必须按 `requirements.txt` 锁 3.6.9。** 详见第 3 节。

> QModMaster 是"上门查账的"——用来读寄存器、确认数据到底写进去没有。**ModRSsim2 是开店铺的，QModMaster 是查账的**，两个都要有。

## 第 3 步：① ② 号角色直接用现成代码（不用从零写）

**① 传感器 和 ② 协议解析 这两个角色的代码已经写好并实测通过了**，在项目仓库的 `代码/modbus/` 目录下：

| 文件 | 属于谁 | 干什么 |
|---|---|---|
| `pointTable.json` | 两边共用 | 点表：地址、标签名、量程、缩放系数 |
| `sensorSim.py` | ① 传感器 | 起 Modbus 从站，假装泵房控制柜造数据 |
| `protocolParser.py` | ② 协议解析 | 读寄存器 → 翻译成标签名 → 还原工程值 |
| `linkCheck.py` | 联调自检 | 一条命令验证双向链路 |
| `requirements.txt` | 两边共用 | 依赖，**版本已锁死** |

### 怎么跑

```bash
cd modbus
pip install -r requirements.txt     # 只装 pymodbus==3.6.9，别自己装最新版

# 窗口 1：启动模拟器（这个窗口不要关）
python sensorSim.py

# 窗口 2：验证链路
python linkCheck.py
```

**看到 `13 / 13 项通过`，第一周的最小 demo 就达标了。**

### 两个人的活分别在哪

| 角色 | 这一周要做的事 |
|---|---|
| ① 传感器 | 读 `pointTable.json` 看懂每个测点；跑起 `sensorSim.py`；试着改里面的参数（比如进水流速），看液位变化快慢有什么不同 |
| ② 协议解析 | 读 `protocolParser.py` 看懂"地址 → 标签名 → 缩放"这三步；跑 `python protocolParser.py --json` 看后端拿到的数据长什么样 |

> `linkCheck.py` 是用来**互相验证**的：它模拟后端的行为，写线圈让泵转起来，再读回来确认。你把 ① 和 ② 的活干完，它应该全绿。

## 卡住了怎么办

1. **卡超过 1 小时，就发群里问**，不要一个人闷三天。这是本项目的头号风险，不是能力问题。
2. **截图要完整**——别只截最后一行报错，往上多截几行，关键信息常在中间。
3. 问的时候说清三件事：**我装的是什么 → 我做到哪一步 → 报的什么错**。
