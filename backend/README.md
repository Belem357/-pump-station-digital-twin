## 三、接口一览（按接口规范 v1.1.1 实现）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/v1/control` | 下发控制指令（start / stop / set_freq / set_mode） |
| GET | `/api/v1/status` | 当前全量状态快照（前端首屏加载时调） |
| GET | `/api/v1/history` | 历史数据曲线（`?tags=tank_level,pipe_pressure&start=..&end=..&interval=1m`） |
| GET | `/api/v1/alarms` | 报警记录查询（时间 / 设备 / 状态筛选 + 分页） |
| GET | `/api/v1/health` | 健康检查（联调排错第一站） |
| GET | `/api/v1/devices` | **扩展接口**：设备讲解数据（参观讲解场景） |
| WS | `/ws/realtime` | 实时推送，500ms 全量，10s 心跳 ping |

### 错误码（接口规范第七节，全部可实现）

| code | HTTP | 触发场景 |
|---|---|---|
| 1001 | 400 | PLC 通信超时 / 写入失败 |
| 1002 | 400 | device_id 非法 |
| 1003 | 400 | command 非法 |
| 1004 | 400 | value 越界（如频率 60Hz） |
| 1005 | 400 | 缺必填字段 |
| 1006 | 409 | **自动模式下拒绝手动指令**（P0 验收项，绕过前端直接调接口也会拦） |
| 1007 | 409 | 故障泵拒绝启动 |
| 1008 | 429 | 同一设备 2 秒内重复下发；**联锁停泵后 30 秒内启泵** |
| 2001 | 500 | 后端内部错误（兜底，绝不裸奔 500） |
| 2002 | 503 | 模拟器未连接 |

### 报警与防抖（交互流程图流程二，全在后端实现）

- **双阈值回差**：液位触发 <25cm、恢复 >30cm，25~30 之间波动不翻转状态
- **时间防抖**：液位跌破 25cm 需**连续 30 秒**才触发报警与联锁停泵
- **启泵禁令**：联锁停泵后 30 秒内拒绝 start（1008）
- 报警记录生命周期：触发写 `active` 记录（含触发值与阈值），恢复补 `time_end`
- 通信中断：连续 5 秒读不到模拟器 → `comm_lost` 报警记录
- 超压只报警**不**停泵（接口规范第十节 #3 建议，待 PM 确认）

## 四、关键设计说明（答辩可能被问）

1. **报警由后端判定**：接口规范 3.3 规定前端不判阈值，`alarm_*` 标志位随推送下发，避免前后端各算一套。
2. **状态以推送为准**：指令下发成功 ≠ 设备真的启动，前端等 WebSocket 推回 `pump_0x_status` 才改 UI。
3. **同步 Modbus 调用全部丢线程池**（`asyncio.to_thread` + 锁）：pymodbus 是同步库，直接调会卡死事件循环，WebSocket 推送会把 HTTP 接口拖挂。
4. **历史数据用 SQLite**：接口规范第十节 #4 允许的降级方案，标准库自带零安装。每 5 秒采样、保留 48 小时、查询时按 interval 分桶取均值，超 2000 点自动放大间隔并返回 `actual_interval`（验收 2-10）。
5. **全量推送**：500ms 推一次全量数据而非增量，前端断线重连后第一条消息即恢复全量状态。

## 五、已知事项（需与 PM / 组内对齐）

1. `GET /api/v1/devices` 是接口规范外的新增接口（支撑课程选题「供水机房参观、供水系统及设备讲解」），按接口规范总则第三条需 PM 在群里公告后并入规范。
2. `today_kwh` 目前直接透传模拟器数值（模拟器带 12.6 基数积分）。接口规范第十节 #5 建议由后端累加计算 + 每日归零，如 PM 采纳需后端改，模拟器侧同时停发该寄存器。
3. 超压联锁与否待 PM 确认（目前只报警不停泵）。
4. 后端默认绑定 `127.0.0.1:8000`（避免防火墙弹窗）。如需同组用别的电脑访问，把 `main.py` 末尾的 `host="127.0.0.1"` 改成 `"0.0.0.0"`，并在 Windows 防火墙放行 8000 端口。

## 六、验收自测

`testBackend.py` 可一键跑常见验收场景（错误码、历史查询、报警触发、WebSocket 心跳），当前 **35/35 项全部通过**。用法：

```bash
# 模拟器和后端都跑起来后，再开一个窗口：
python testBackend.py
```

脚本自带「安全液位等待」：控制链路一节开始前会等液位 ≥ 40cm、低液位报警恢复、
启泵禁令过期，避免上一轮测试抽干水箱导致误报；结尾会把泵停干净再退出。

自测覆盖不到的长周期场景（联锁 30 秒、通信中断、泵故障），已用注入脚本逐项验证过：

| 场景 | 结果 |
| --- | --- |
| 泵故障拒启（寄存器注入状态=2 → 1007） | ✅ HTTP 409 code=1007 |
| 泵故障报警生命周期（触发 → 恢复） | ✅ 记录 A20260927007/08 完整闭合 |
| 通信中断（杀模拟器 → 2002 + comm_lost，重启模拟器自动恢复） | ✅ HTTP 503 code=2002，A20260927010 触发/恢复 |
| 低液位联锁（抽干水箱 → 联锁停泵 → 30 秒禁令 1008 → 过期后可启） | ✅ HTTP 429 code=1008，禁令后 code=0 且泵真实运行 |

## 七、健壮性说明（联调中踩过的坑）

1. 协议解析器（`protocolParser.py`，协同文件）连接断开时 `read_holding_registers` 会直接抛异常，与文档「失败返回 None」不一致。后端读循环已兜底：读异常统一按「读不到数据」处理，comm_lost 计时和快照清空都正常走。
2. 主循环单周期异常只跳过不退出（曾经报警文案模板格式化错误把整个读循环炸掉、HTTP 层带着旧快照「装活」，已修复并加保护）。
3. 后端启动时会把数据库里遗留的 active 报警闭合为 recovered（标注「服务重启」），避免引擎状态归零后记录与实际不符。
4. 本机如果 8000 端口被占（报 winerror 10048），多半是上次的后端没关干净，任务管理器结束 python 进程即可。
