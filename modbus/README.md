# 泵房数字孪生 · Modbus 模拟器与协议解析

这里放的是 **① 传感器与设备模拟** 和 **② 协议解析** 两个角色的代码。两个文件、一张点表，能直接跑。

| 文件 | 属于谁 | 干什么 |
|---|---|---|
| `pointTable.json` | **两边共用** | 点表：地址、标签名、量程、缩放系数。唯一数据源，谁都不许各改各的 |
| `sensorSim.py` | ① 传感器与设备模拟 | 起一个 Modbus 从站，假装是泵房控制柜，持续造数据、响应指令 |
| `protocolParser.py` | ② 协议解析 | 读寄存器 → 翻译成标签名 → 还原工程值 → 交给后端 |
| `requirements.txt` | 两边共用 | 依赖，**版本已锁死** |

---

## 一、安装（两边都要做）

```bash
pip install -r requirements.txt
```

> ⚠️ **不要**直接 `pip install pymodbus` 装最新版。pymodbus 3.10 之后 API 正在向 4.0 迁移，最新的 3.15 里经典接口已经被移除，写模拟器会直接报错。所以这里锁死在 `3.6.9`。

---

## 二、怎么跑（两边都要开两个窗口）

**窗口 1 —— 启动模拟器（① 号角色）**

```bash
python sensorSim.py
```

看到「泵房模拟器已启动」就成了。**这个窗口不要关**，它会每 200ms 推进一次数据。

**窗口 2 —— 启动协议解析（② 号角色）**

```bash
python protocolParser.py            # 持续采集，打印可读状态
python protocolParser.py --json     # 持续采集，打印后端要用的 JSON
python protocolParser.py --once     # 只读一次就退出，最快验证链路
```

### 预期看到什么

窗口 2 应该每 5 秒打印一行，数值在变：

```
  水箱液位 82.3cm | 出水总管压力 0.48MPa | 1#泵状态 运行 | 1#泵频率 40.0Hz | ...
```

看到这行，说明 **① → ② 这条链路通了**，第一周的最小 demo 就完成了。

## 三、用 QModMaster 独立验证（可选但推荐）

怀疑「数据到底写进去没有」时，用 QModMaster 直接看寄存器：

1. 打开 QModMaster
2. Mode 选 **TCP**，IP `127.0.0.1`，Port `502`，点 **Connect**
3. Slave ID 填 `1`，Function 选 `Read Holding Registers (0x03)`
4. Address 填 **`0`**，Quantity 填 **`21`**，点 **Send**

> ⚠️ **Address 填 0 不是 1。** 文档里写的地址是 `40001`，但代码里的地址要**减 1**，这是 Modbus 的两套叫法，新手最常踩的坑。填 1 会读到 40002 的值，而且不报错。

第 1 个值应该是液位 ×10（比如 823 代表 82.3cm）。

## 四、点表里的两个特殊点

**1. `today_kwh`（40012~40013）是全表唯一的特例**

其他所有测点都是「存整数 × 缩放系数」（液位 85.5 存成 855）。只有它走 IEEE754 32 位浮点，**占两个寄存器，高字在前**，不做整数缩放。代码里 `float32ToWords` / `wordsToFloat32` 两个函数专门处理它，别套用 ÷10 那套。

> **耗电量为什么由模拟器提供，而不是后端累加？**
>
> 这一点两份文档原本是矛盾的：PRD §9 待决策 #5 说「由后端根据电流与运行时长累加，不要求模拟器提供」，但《接口规范》第四节把 40012~40013 列进了 Modbus 地址表。
>
> **本项目按《接口规范》走，即模拟器（扮演电度表）提供。** 理由：真实泵房里耗电量是电度表**量**出来的，不是算出来的；而且后端一重启，自己累加的数就没了，与「今日」这个语义不符。
>
> 因此 `sensorSim.py` 里的 `KWH_INITIAL = 12.6` 给了个起始基数（12.6 取自《接口规范》5.2 节示例）。不给基数的话，泵跑几秒才 0.004 度，演示时看着不真实。
>
> **待办**：需 PM 把 PRD §9 的这条待决策标记为「已决策：改由模拟器（电度表）提供」，两处文档才算对齐。

**2. `40016~40019` 是故意留空的**

从 40015 直接跳到 40020。将来要加测点（比如补水质），从这里往后接，老地址一个都不用动。

## 五、控制指令怎么走（第 5 周会用到）

模拟器响应 5 个线圈：

| 线圈 | 地址 | 作用 |
|---|---|---|
| `pump_01_cmd_start` | 00001 | 写 1 启动 1# 泵 |
| `pump_01_cmd_stop` | 00002 | 写 1 停止 1# 泵 |
| `pump_02_cmd_start` | 00003 | 写 1 启动 2# 泵 |
| `pump_02_cmd_stop` | 00004 | 写 1 停止 2# 泵 |
| `sys_cmd_set_mode` | 00005 | 切换手/自动 |

**线圈是一次性脉冲**：模拟器执行完动作后会自己复位成 0。这样后端下次再写 1 时，模拟器能分清是新指令还是上次的残留。

手动模式下 `sys_mode = 0`；切到自动模式后，模拟器会按液位自行控泵（高于 90cm 启泵、低于 40cm 停泵），并且**拒绝手动启停指令**——这对应 PRD 里「自动模式下屏蔽手动按钮」那条要求。

## 六、已经实现的保护逻辑

**低液位联锁停泵（PRD F10，P0）**：液位低于 25cm 且**持续 30 秒**，模拟器自动切断所有运行中的泵，防止空转烧毁。带 30 秒防抖，避免液位在阈值附近波动时频繁启停。

想验证它：在 QModMaster 里把 40001 改成 200（即 20cm，低于 25），保持 30 秒，观察模拟器窗口打印的联锁日志。

## 七、常见问题

| 现象 | 原因与解决 |
|---|---|
| `端口绑定失败` | 502 端口被占用。把 `pointTable.json` 里的 `port` 改成 `5020`，`protocolParser.py` 用同一份配置会自动跟着改 |
| 窗口 2 报「连不上」 | 窗口 1 的模拟器没启动，或两边端口不一致 |
| `ModuleNotFoundError: pymodbus` | 没装依赖，跑 `pip install -r requirements.txt` |
| 报 `ImportError: cannot import name 'ModbusSlaveContext'` | 装成了新版 pymodbus。卸掉重装：`pip uninstall pymodbus -y` 再 `pip install -r requirements.txt` |
| 读出来的数全是 0 | QModMaster 里 Address 填了 1 而不是 0（见第三节） |
