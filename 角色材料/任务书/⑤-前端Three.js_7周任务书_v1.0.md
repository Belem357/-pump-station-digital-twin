## 二、现状（开工前先看一遍）

### 2.1 3D 已经改成"配置驱动"

`scene.html` 启动时 `fetch('./sceneConfig.json')`，配置里有六个段：

| 段 | 内容 |
|---|---|
| `model` | 模型路径、抬高量 |
| `camera` | fov、背景、雾、自动取景倍数 |
| `views` | **4 个预设视角**（全景 / 液罐聚焦 / 电机聚焦 / 俯视）——都是"**盯住某个节点 + 相对偏移**"，不写死坐标 |
| `statusVisual` | 状态配色：`0=停止` / `1=运行(绿)` / `2=故障(红闪)` |
| `tank` | 水箱液位可视化参数（量程、液柱半径比例、水色） |
| `pumps` | 每台泵的**状态节点**、**转子零件清单** |
| `hotspots` | **点击热区**：设备 → 节点名数组（为"点设备弹讲解"准备，**前端还没接上**） |

**取不到配置会退回内置兜底，不会白屏。**

### 2.2 三个页面

| 页面 | 说明 |
|---|---|
| `pump` | **默认页**，简化监控（液位/压力/泵控制） |
| `scene` | **3D 大屏**，点"进入 3D 大屏 →"按钮进入 |
| `data` | 数据面板（历史曲线、报警记录、设备讲解卡片） |

## 三、每周任务

### W1（10-15 四 ~ 10-21 三）｜压力设定值控件

#### W1-1 压力设定值控件 + 目标值/实际值双线 ｜ 1.5 天 ｜ **本周主任务**

**要做什么**：
- 加一个**压力设定值输入控件**（滑杆或数字框），调用 ③ 的新接口把设定值写下去
- 图表上画**两条线**：目标值（虚线）+ 实际值（实线），能直观看泵有没有"跟上"

**为什么**：W1 的演示主题是**恒压变频**。导师要看的不是"压力是多少"，而是"**我改了目标值，泵有没有自动跟上去**"。**这个控件就是演示的操作入口**。

**怎么做**：
- 报警文案要改：现在报的是"压力超过 0.8 MPa"（越上限），恒压后是**"偏离设定值"**（高了低了都报）。**文案跟 ③ 对齐**，别各写各的。
- 设定值默认放在 **0.45 MPa** 左右（介于中压 0.50 与低压 0.30 之间，演示好用）

**验收标准**：拖动设定值 → 泵频率变化 → 实际压力曲线向目标值靠拢；偏离超过阈值时报警条出现。

### W2（10-22 四 ~ 10-28 三）｜信息架构设计 —— **不写代码**

#### W2-1 三区 UI 信息架构设计 ｜ 1.5 天 ｜ **本周唯一任务**

**要做什么**：**先设计，再写代码。**

**为什么**：《12》风险表第四条写得很直白——"⑤ UI 重构风险：侧边栏从 8 个数值到 20+ 个。**先做信息架构设计（分区折叠方案）再写代码，别边写边改**"。

**要设计什么**：
- 侧边栏要展示 **6 泵 × 3 参数 + 3 区压力 + 公共量（液位/罐压/电量×4）**，平铺的话是 **20+ 个数值**
- 怎么做**分区折叠**？默认展开哪个区？报警的区要不要自动展开？
- 移动端 / 小屏怎么办？

**交付物**：一页纸的**信息架构草图**（截图或手绘拍照都行）+ 与 ⑥ 确认。**这张图要发群里让大家评审，不要自己定完就开工。**

**⚠️ 这一周看起来"没产出"，但它决定了 W3~W4 会不会返工。** 可以在演示时给导师看这张设计图——**本身就是可以展示的进展**。

### W4（11-05 四 ~ 11-11 三）｜3D 三区化 + 点设备弹讲解

#### W4-1 3D 场景三区化 ｜ 1.5 天

- 6 台泵的转子动画、状态着色（配置里 `pumps` 数组扩到 6 项）
- 分区标牌/视觉分组，让 3D 里能一眼分出三个区
- 预设视角补"高压区/中压区/低压区"三个

#### W4-2 **`Raycaster` 点 3D 设备弹讲解卡片** ｜ 1.5 天 ｜ **导师最想要的那个**

**要做什么**：点 3D 场景里的设备 → 弹出该设备的讲解卡片。

**为什么**：本课程的选题就是"**供水机房参观、供水系统及设备讲解**"，而**现在全文件 0 处 `Raycaster`**——点设备没有任何反应。**这是选题的核心交互，缺了它"讲解"两个字落不了地。**

**好消息**：数据**已经全部就绪**，你只需要接线：
- 后端 `GET /api/v1/devices` 已返回讲解数据（名称、分类、描述、传感器型号）
- **`sceneConfig.json` 的 `hotspots` 段已经把"设备 → 节点名数组"的映射写好了**（第一批 6 个设备，53 个节点名已验证全部存在于模型里）

**⚠️ 一个必须处理好的细节**（第二轮任务书里就强调过）：

> **点水泵时可能命中 `pump_01_motor` 或 `pump_01_body`（两个节点），要做父子/同名归组**，别出现"点电机弹一个卡片、点泵体弹另一个"。
>
> `hotspots` 里每台泵已经挂了 7 个节点（电机、泵体、进口法兰、出口立管、底座、接线盒、风扇罩），**它们都该弹同一张卡**。

**验收标准**：
1. 点 1# 泵 → 弹对应卡片，**不会因为点到电机壳/泵体而弹错**
2. 点水箱、进水阀、出水总管、控制柜 → 各自弹对应卡片
3. 点到空地/地面 → 不弹卡片
4. 卡片能关掉
