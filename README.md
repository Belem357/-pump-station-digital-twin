## 一、这个项目在做什么

**一句话**：小区自来水管网压力不够，要在中途设个泵房二次加压。这个项目就是给这样一个泵房做一个**网页版的实时监控系统**——设备状态在 3D 模型上跟着真实数据动，能远程启停水泵，越限会报警。

**数据链路**（每个人对号入座，就知道自己在哪一环）：

```
[传感器: 造数据] → [协议解析: 读出来+翻译] → [后端: 存起来+推给网页] → [前端: 收到数据+让3D动起来]
                                                      ↑                        ↓
                                        [写 Modbus 线圈] ← ← ← [控制指令下发]

[三维: 提供 3D 模型文件] →
[产品经理: 定规矩(字段名)、盯进度、对接口、备演示 —— 贯穿全程]
```

> ⚠️ **本项目没有真实泵房**，所有设备由软件模拟器顶替。但 **Modbus 通信协议是真的保留**——将来接实体泵房，只需把连接地址从模拟器换成真 PLC 的 IP，代码不用改。

## 四、最短上手路径（① ② 号角色）

```bash
cd modbus
pip install -r requirements.txt      # 只装一个包，版本已锁死

# 窗口 1：启动模拟器（别关）
python sensorSim.py

# 窗口 2：验证链路
python linkCheck.py                  # 看到 13/13 通过就算通了
```

> ⚠️ **别直接 `pip install pymodbus`**。最新版把经典接口移除了，装上会报 `ImportError`。必须按 `requirements.txt` 锁 `3.6.9`。

## 五、几条全组约定

1. **字段命名以 `03.接口规范与数据字典` 为唯一标准**。同一样东西不许有两个名字。
2. **Modbus 地址是双方契约**。① 号角色建点时照 `05.建点表` 建；确实要改地址，必须同时改 `03.接口规范` 并通知全组。
3. **报警由后端判定**，前端只负责显示。前后端各判一套会导致状态不一致（`03` 第 3.3 节）。
4. **卡住超过 1 小时就发群里问**，别一个人闷三天。
5. **每周三上午演示**，所以一周的节奏是「周四开工 → 下周三演示」。
