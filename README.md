# 小型二供泵房数字孪生监控系统

**课程项目 · 6 人团队 · 工期 12 周 **

> 新人第一次打开这个仓库，**从这份 README 看起**。它会告诉你：你在链路哪一环、要看哪几份文件、怎么把代码跑起来。

## 一、这个项目在做什么

**一句话**：小区自来水管网压力不够，要在中途设个泵房二次加压。这个项目就是给这样一个泵房做一套**网页版实时监控系统**——设备状态在 3D 模型上跟着真实数据动，能远程启停水泵，越限会报警。

**数据链路**（对号入座，就知道自己在哪一环）：

```
[传感器: 造数据] → [协议解析: 读出来+翻译] → [后端: 存起来+推给网页] → [前端: 收到数据+让3D动起来]
                                                      ↑                        ↓
                                        [写 Modbus 线圈] ← ← ← [控制指令下发]

[三维: 提供 3D 模型文件] →
[产品经理: 定规矩(字段名)、盯进度、对接口、备演示 —— 贯穿全程]
```

> ⚠️ **本项目没有真实泵房**，所有设备由软件模拟器顶替。但 **Modbus 通信协议是真的保留**——将来接实体泵房，只需把连接地址从模拟器换成真 PLC 的 IP，代码不用改。

## 三、文件怎么放的（为什么这么分）

```
泵房/
├── 共享文档/          ← 人人要看的，只存一份，谁都不许私自改副本
├── 角色材料/          ← 只有某个角色才用的
│   └── 传感器与协议解析/
├── 一键启动.bat       ← 双击这个跑起整个系统（放根目录，自动找 代码/backend/）
├── 代码/              ← 能跑的东西
│   ├── modbus/        ← ① ② ③ 三个角色共用（分不开，故意放一起）
│   ├── backend/       ← ③ 后端正式服务（FastAPI + WebSocket + SQLite）
│   └── frontend/      ← ⑤ 前端
├── 泵房.glb           ← 三维交付的泵房模型，节点名已按 03 规范对齐后端
├── 模型升级路线图.md   ← 模型现状的短板清单（无贴图/无环境反射/无可动结构/点不了设备）与升级方向
├── 资料/              ← 课程/导师给的参考材料，不是我们的产出
└── _工具/             ← 内部小工具
    ├── fixGlbNodeNames.mjs  ← 三维重新导出模型后，用它重新对齐节点名
    ├── validateGlb.mjs      ← 校验 GLB 结构（顶点/索引/包围盒），对齐后跑一遍
    ├── docx2txt.py          ← .docx 正文抽成文本（md2docx.py 的反向）
    ├── md2docx.py           ← .md 源稿生成 .docx 成品
    └── push-all.bat         ← 一键推送两个远程
```

**为什么共享文档不按角色拆开？** 因为 `03.接口规范` 被 ① 看第四节、② 看第三节、③⑤ 看第五六节——它是全组契约，不是谁的私产。如果按角色拆成六份副本，改一处忘同步就变成六个版本。**你们文档里已经出过一次同类问题**（`device` vs `device_id`、`action` vs `command` 两处字段名冲突，本质就是同一件事有两个版本）。所以共享的集中放，角色独占的才分开。

## 四之二、跑起整个系统（一条命令）

**双击仓库根目录的 `一键启动.bat`**（或者桌面上的「泵房数字孪生」快捷方式）就行。它会：

1. 弹出「Pump-1 simulator」窗口（Modbus 服务端，监听 127.0.0.1:502）
2. 等 3 秒，弹出「Pump-2 backend」窗口（HTTP + WebSocket，监听 8000）
3. 再等 7 秒，自动打开浏览器到 `http://127.0.0.1:8000/`

**那两个窗口不能关**，关了系统就停了。

> 根目录这份启动器**不写死源码目录名**——它会在运行时扫描子目录，找到含 `backend/sensorSim.py` 的那个（也就是 `代码/backend/`）。所以源码目录改名、或者仓库被克隆到别的机器，它都还能用。（不能写死的原因见下面那条 ASCII 警告：`代码` 是中文，写进 `.bat` 会让 cmd 解析器错位。）
>
> 想手工分窗口跑，就开两个终端：
> ```
> cd 代码\backend
> python sensorSim.py      # 窗口 1，别关
> python main.py           # 窗口 2，别关
> ```

> ⚠️ **`.venv` 不能从别人机器上拷**。虚拟环境里写死了创建时的解释器绝对路径，换台机器必然失效（本项目 `.gitignore` 已把它排除就是这原因）。两个启动脚本都会**实际执行一次**来验证 Python 能不能跑，坏了自动退回系统 `python`；都没有就给出重建虚拟环境的命令。手工重建：
>
> ```
> cd 代码\backend
> python -m venv .venv
> .venv\Scripts\pip install -r requirements.txt
> ```

> ⚠️ **改这两个 `.bat` 时：内容必须保持纯 ASCII，行尾必须是 CRLF。**
> cmd.exe 的批处理解析器按字节偏移读文件——只要出现一个多字节中文行，偏移就会算错，
> 解析器从中途续读，后面的行被当成命令执行，报一堆「`'to'` 不是内部或外部命令」，
> 整个启动脚本就废了。**中文提示请放到 Python 侧打印**（`main.py` 的启动横幅已经是中文的）。
> 行尾由 `.gitattributes` 的 `*.bat text eol=crlf` 兜底，别手工改成 LF。

**⑤ 前端**：不要双击 `scene.html` 打开。

> ⚠️ 这个页面**必须联网**——它从 CDN 加载 Three.js、Vue 和 ECharts。实测下载 `three.module.js` 要 9 秒，评审现场网络差或断网会**直接白屏**。
> ⚠️ **页面要加载 `.glb` 模型，所以不能走 `file://`。** 浏览器从 `file://` 页面读本地 `.glb` 会被同源策略拦掉，表现就是"模型加载失败"、只剩地面和 UI。

**推荐做法：直接跑后端，一个地址全给。** 后端已经把前端页面、3D 模型、REST 接口和 WebSocket 全挂在同一个端口上（`代码/backend/main.py` 末尾的静态挂载 + `/model.glb` 路由）：

```bash
cd 泵房/代码/backend
python main.py
# 完整系统：http://127.0.0.1:8000/
# 接口文档：http://127.0.0.1:8000/docs
# 3D 模型：http://127.0.0.1:8000/model.glb
```

启动时会打印本机的局域网地址（形如 `http://192.168.x.x:8000/`）。——答辩时导师用自己手机就能看，不用在你电脑上装任何东西。

> ⚠️ **首次绑定 `0.0.0.0` 后，Windows 防火墙会拦入站 8000 端口**，会弹窗问是否允许，选"允许"。如果没弹窗、或者当时点了拒绝，症状是**导师手机连不上、但你自己用 `127.0.0.1` 能连**——就是这个原因。
>
> ⚠️ **前端代码里 WebSocket 地址不许写死 `127.0.0.1`**：在导师手机上 `127.0.0.1` 指的是手机自己，必然连不上。要从页面自身地址推导：
>
> ```js
> const wsUrl = (location.protocol === 'https:' ? 'wss://' : 'ws://')
>             + location. host + '/ws/realtime';
> ```

## 五、几条全组约定

1. **字段命名以 `03.接口规范与数据字典` 为唯一标准**。同一样东西不许有两个名字。
2. **Modbus 地址是双方契约**。① 号角色建点时照 `05.建点表` 建；确实要改地址，必须同时改 `03.接口规范` 并通知全组。
3. **报警由后端判定**，前端只负责显示。前后端各判一套会导致状态不一致（`03` 第 3.3 节）。
4. **卡住超过 1 小时就发群里问**，别一个人闷三天。
5. **每周三上午演示**，所以一周的节奏是「周四开工 → 下周三演示」。
6. **三维重新导出模型后，必须跑一遍对齐和校验**，否则前端按名字找不到节点、只会看到地面：
   ```bash
   node _工具/fixGlbNodeNames.mjs 泵房.glb 泵房.glb   # 节点名对齐后端
   node _工具/validateGlb.mjs     泵房.glb            # 校验结构完整
   ```
   `代码/backend/devices.json` 的 `node3d` 字段就是模型要满足的节点名清单。**注意 `/api/v1/devices` 这个接口不在接口规范 v1.1.1 里**，是后端为讲解场景加的扩展，所以对齐的依据是这份文件、不是 `03`。

## 六、代码推送到哪（两个仓库）

这个项目**同时推到两个地方**，内容完全一样：

| 远程名 | 地址 | 分支 | 谁要求 |
|---|---|---|---|
| `origin` | GitHub · `Belem357/-pump-station-digital-twin` | `main` | 我们自己用 |
| `gitee` | Gitee · `lichu-like/chizhouxueyuan25jike1ban8` | `master` | **老师要求** |

**一键推两个**：双击 `_工具/push-all.bat`（或在命令行跑它）。

> **为什么 Gitee 那边是 `master` 不是 `main`**：那个仓库是老师建的，默认分支就叫 `master`。我们本地的分支叫 `main`，所以推送命令写成 `git push gitee main:master`（把本地的 main 推成远程的 master）。
>
> **为什么第一次要 `--force`**：老师那个仓库建的时候生成了一个空白初始提交，和我们的历史没有共同祖先，不强推会被拒。**那次已经做完了**，之后正常推就行——`push-all.bat` 里用的是普通推送，没有 `--force`。
